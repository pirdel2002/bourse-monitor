# Bourse Monitor

سامانه شخصی پایش شرط‌های بورس تهران و ارسال هشدار تلگرام. این برنامه سفارش واقعی ثبت نمی‌کند.

## قابلیت‌ها

- تعریف شرط به زبان فارسی
- تعریف بصری قواعد و گروه‌های تو‌در‌توی `AND` و `OR`
- جست‌وجوی نماد از فهرست محلی
- قواعد قیمت، عبور، تثبیت، محدوده، برگشت، قدرت خریدار، نسبت تقاضا و عرضه و صف
- زمان شروع، پایان و فاصله بررسی مستقل برای هر پایش
- اقدامات خرید، میانگین کم‌کردن، فروش در حد زیان و فروش برای سیو سود
- درج تعداد، قیمت پیشنهادی و مبلغ تقریبی در هشدار تلگرام
- جلوگیری از اعلان تکراری؛ اعلان هنگام تغییر حالت به «فعال»
- ذخیره تاریخچه، Snapshot و مصرف API در SQLite با WAL
- محدودیت پایدار روزانه و پنج‌دقیقه‌ای برای هر API
- اشتراک یک پاسخ `AllSymbols` بین تمام شرط‌های سررسیدشده
- Docker Compose، Healthcheck و نصب تک‌خطی روی Ubuntu VPS
- رابط Responsive با فونت وزیر و منوی همبرگری موبایل
- ورود ماندگار اختیاری ۳۰روزه با نشست هش‌شده در دیتابیس
- تقویم شمسی، ارقام فارسی و میانبرهای آگاه از روزهای معاملاتی
- ورود گروهی پایش‌ها با Paste یا فایل TXT/JSON
- چند ربات تلگرام و چند کلید BRSAPI با حالت‌های اتوماتیک، بالانس و فالبک
- Backup و Restore رمزگذاری‌شده برای مهاجرت کامل سرور
- بازیابی رمز مدیر با کد یک‌بارمصرف تلگرام
- صفحه تحلیل اندیکاتور هر نماد با RSI، MFI، MACD، OBV، EMA، ATR، BBW و حجم نسبی
- جست‌وجوی Ajax نماد در تمام ورودی‌های نماد، با اولویت نام نماد و سپس نام شرکت
- Rule Engine عمومی نسخه ۲ با محاسبه محلی اندیکاتورها و جلوگیری از هشدار تکراری

## صفحه تحلیل اندیکاتورها

از منوی «تحلیل اندیکاتورها» نماد یا نام شرکت را جست‌وجو کنید. برنامه تاریخچه روزانه را یک‌بار از `Candlestick` می‌گیرد، در SQLite نگه می‌دارد و کندل موقت روز جاری را با داده همان Snapshot سراسری `AllSymbols` می‌سازد. بنابراین بازکردن دوباره صفحه یا ارزیابی چند Rule برای یک نماد، درخواست جداگانه برای هر اندیکاتور ایجاد نمی‌کند.

در این صفحه چهار گروه نمایش داده می‌شود:

- نوسان‌گرها: `RSI14`، `MFI14` و `MACD 12/26/9`
- روند: `EMA20`، `EMA50` و فاصله درصدی آن‌ها
- حجم و جریان پول: `OBV`، نسبت حجم به میانگین ۲۰روزه و قدرت خریدار
- نوسان: `ATR14` و `BBW`

اگر سابقه کافی نباشد، مقدار «داده ناکافی» نمایش داده می‌شود و برنامه مقدار ساختگی تولید نمی‌کند. نخستین تحلیل هر نماد ممکن است یک سهم از API روزانه `Candlestick` مصرف کند؛ دفعات بعد از Cache محلی استفاده می‌کنند.

## معماری Rule Engine نسخه ۲

```text
BRSAPI AllSymbols -> Snapshot مشترک -> Cache/SQLite -> Indicator Engine -> Rule Engine -> Telegram/Dashboard
```

- یک Snapshot بازار تمام Ruleهای سررسیدشده را تغذیه می‌کند.
- EMA، RSI، MACD، MFI، OBV، ATR، BBW و `Volume SMA20` داخل برنامه محاسبه می‌شوند.
- حالت هر Rule ذخیره می‌شود و هشدار فقط در گذار `false -> true` ارسال می‌شود.
- `cooldown_minutes` و `once_per_day` محدودیت‌های مستقل هر Rule هستند.
- Ruleهای قدیمی حذف یا تبدیل اجباری نمی‌شوند و هم‌زمان با موتور جدید کار می‌کنند.
- Migration دیتابیس هنگام شروع برنامه خودکار و backward-compatible است.

### Rule Pack پیش‌فرض

Rule Pack تاریخ `۱۴۰۵/۰۷/۰۳` در اولین اجرای نسخه جدید به‌صورت idempotent نصب می‌شود. این بسته شامل ۲۲۱ Rule برای نامزدهای خرید، Watchlist، سبد فعلی و وضعیت کل بازار است. Ruleهای موجود حذف یا بازنویسی نمی‌شوند. اگر یک Rule از صفحه «پایش‌های فعال» حذف شود، با Restart دوباره ساخته نمی‌شود.

- هشدار فقط در تغییر حالت شرط از برقرارنبودن به برقرارشدن ارسال می‌شود.
- Cooldown قواعد `BUY/WATCH` برابر ۴۵ دقیقه و قواعد `WARNING/SELL/EXIT` برابر ۱۵ دقیقه است.
- در `MARKET_RISK_OFF`، شدت `STRONG_BUY` به `BUY` و شدت `BUY` به `WATCH` کاهش می‌یابد.
- قواعد `SELL` و `EXIT` در وضعیت منفی بازار بدون تغییر می‌مانند.
- Rule عمومی سود ۵ درصد فقط `PROFIT_REVIEW` است؛ سود ۹ درصد می‌تواند `PARTIAL_PROFIT` ایجاد کند.
- امتیاز بازیابی تکنیکی از ۸ مؤلفه محاسبه و در صفحه تحلیل نمایش داده می‌شود.

در فرم «پایش جدید»، تب «قاعده‌ساز اندیکاتورها» برای ساخت Ruleهای v2 اضافه شده است. این تب Conditionهای MACD، RSI، MFI، OBV، EMA، حجم، قدرت خریدار، سبد، بازار و امتیاز ترکیبی را نمایش می‌دهد.

شرط‌های عمومی موتور جدید از مسیر `GET /api/meta` در بخش `conditionsV2` قابل مشاهده‌اند. Rule جدید با `POST /api/rules` ثبت می‌شود و می‌توان موتور را برای آزمایش دستی با `POST /api/rules/run` اجرا کرد. نمونه:

```json
{
  "ruleId": "BENERO_BREAKOUT_3900",
  "symbol": "بنیرو",
  "name": "شکست مقاومت بنیرو",
  "scope": "SYMBOL",
  "severity": "BUY",
  "expression": {
    "op": "AND",
    "conditions": [
      {"type": "PRICE_CROSS_ABOVE", "value": 3900},
      {"type": "VOLUME_RATIO_ABOVE", "value": 1.5},
      {"type": "BUYER_POWER_ABOVE", "value": 1.2}
    ]
  },
  "action": "BUY_ALERT",
  "cooldownMinutes": 60,
  "intervalMinutes": 5
}
```

## نصب تک‌خطی روی VPS

دستور زیر برنامه را در `/opt/bourse-monitor` نصب می‌کند و فقط روی `127.0.0.1:3000` در دسترس قرار می‌دهد:

```bash
curl -fsSL https://raw.githubusercontent.com/pirdel2002/bourse-monitor/main/install.sh | sudo bash
```

اسکریپت کلید BRSAPI، توکن ربات و Chat ID را در ترمینال درخواست می‌کند. مقادیر محرمانه نمایش داده نمی‌شوند و وارد History شل نیز نمی‌شوند. سپس یک `ADMIN_TOKEN` تصادفی تولید و در پایان فقط یک‌بار نمایش می‌دهد. برای نصب خودکار در CI می‌توانید متغیرها را همراه `NONINTERACTIVE=1` ارسال کنید.

برای بازکردن امن داشبورد از کامپیوتر خود:

```bash
ssh -L 3000:127.0.0.1:3000 USER@VPS_IP
```

سپس `http://127.0.0.1:3000` را باز کنید و توکن مدیریت را وارد کنید.

برای انتشار مستقیم داشبورد روی اینترنت، ابتدا HTTPS و Reverse Proxy نصب کنید. قراردادن داشبورد روی HTTP عمومی توصیه نمی‌شود.

## دسترسی عمومی موبایل بدون پورت ۸۰ و ۴۴۳

برنامه روی `127.0.0.1:3000` باقی می‌ماند. اگر پورت‌های ۸۰ و ۴۴۳ سرور در اختیار VPN هستند، یک Cloudflare Tunnel بسازید و Public Hostname آن را به سرویس زیر متصل کنید:

```text
http://app:3000
```

توکن Tunnel را هنگام اجرای `install.sh` وارد کنید. نصب‌کننده فایل `compose.tunnel.yaml` را خودکار فعال می‌کند. در این حالت هیچ پورت عمومی جدیدی باز نمی‌شود و موبایل از HTTPS دامنه استفاده می‌کند.

اجرای دستی Tunnel:

```bash
docker compose -f compose.yaml -f compose.tunnel.yaml --env-file .env up -d --build
```

پورت `3000` را با HTTP خام روی اینترنت منتشر نکنید. رمز ورود، کلید API و فایل پشتیبان از این مسیر عبور می‌کنند.


## محدودیت API

محدودیت‌ها فقط تنظیم ظاهری نیستند. مصرف هر endpoint پیش از درخواست در تراکنش دیتابیس رزرو می‌شود. ری‌استارت برنامه شمارنده را صفر نمی‌کند.

پیش‌فرض‌ها:

| API | روزانه | هر پنج دقیقه |
|---|---:|---:|
| AllSymbols | 100 | 2 |
| Symbol | 10 | 2 |
| Index | 100 | 2 |
| Candlestick | 10 | 2 |
| مجموع همه APIها | — | 300 |

مقادیر را دقیقاً مطابق بسته BRSAPI خود در `.env` تنظیم کنید. `MARKET_CACHE_SECONDS=150` باعث می‌شود چند شرط هم‌زمان فقط یک درخواست `AllSymbols` مصرف کنند. جست‌وجوی نماد نیز از دیتابیس محلی انجام می‌شود و به‌ازای هر حرف API را فراخوانی نمی‌کند.

اگر سهمیه تمام شود، برنامه درخواست را ارسال نمی‌کند و خطای `API_QUOTA_EXCEEDED` ثبت می‌شود.

تمام درخواست‌های BRSAPI با `User-Agent` صریح و قابل تنظیم ارسال می‌شوند. مقدار پیش‌فرض مشابه Chrome دسکتاپ است. آن را حذف نکنید؛ درخواست بدون `User-Agent` معتبر ممکن است باعث مسدودی IP سرور شود.

## راهنمای قواعد نوشتاری فارسی

Parser متن فارسی قطعی است و جمله را حدس نمی‌زند. عبارت را با یکی از الگوهای این جدول بنویسید. ارقام فارسی و انگلیسی و جداکننده هزارگان پذیرفته می‌شوند.

| هدف | الگوی معتبر | نتیجه داخلی |
|---|---|---|
| قیمت بالاتر از سطح | `قیمت بیشتر از ۳۳۰۰` | `lastPrice > 3300` |
| قیمت پایین‌تر از سطح | `قیمت کمتر از ۲۴۰۰` | `lastPrice < 2400` |
| عبور صعودی | `عبور به بالای ۱۴۸۵` | نمونه قبلی ≤ سطح و نمونه فعلی > سطح |
| تثبیت بالای سطح | `تثبیت بالای ۳۳۰۰` | سه نمونه متوالی بالای سطح |
| تثبیت پایین سطح | `تثبیت پایین‌تر از ۲۴۵۰` | سه نمونه متوالی پایین سطح |
| برگشت از محدوده | `برگشت از محدوده ۱۲۶۰۰ تا ۱۲۹۰۰` | تماس قبلی با محدوده و سپس خروج از سقف آن |
| قدرت خریدار | `قدرت خریدار بیشتر از ۱.۳` | `buyerPower > 1.3` |
| نسبت تقاضا به عرضه | `تقاضا ۲ برابر عرضه` | `bidAskRatio >= 2` |
| جمع‌شدن صف فروش | `جمع شدن صف فروش` | صف فروش قبلی وجود داشته و اکنون صفر شده است |
| تشکیل صف خرید | `تشکیل صف خرید` | صف خرید قبلاً صفر بوده و اکنون مثبت شده است |

صورت‌های هم‌معنی محدود زیر نیز پذیرفته می‌شوند:

- `حفظ قیمت بالای ۳۳۰۰`
- `پس گرفتن ۳۳۰۰`
- `عبور از ۳۳۰۰`
- `جمع شود صف فروش`
- `حجم تقاضا ۲ برابر عرضه`

### ترکیب `و` و `یا`

- `و` یعنی همه شرط‌ها باید برقرار باشند (`AND`).
- `یا` یعنی برقرارشدن حداقل یک شرط کافی است (`OR`).
- اولویت اجرا با `و` است. عبارت `A یا B و C` به‌شکل `A OR (B AND C)` تفسیر می‌شود.
- پرانتز در متن فارسی پشتیبانی نمی‌شود. برای ساختار پیچیده از قاعده‌ساز یا JSON ساختاریافته استفاده کنید.

نمونه‌ها:

```text
تثبیت بالای ۳۳۰۰ و قدرت خریدار بیشتر از ۱.۳
جمع شدن صف فروش و عبور به بالای ۱۴۸۵
قیمت کمتر از ۲۴۰۰۰ یا تثبیت پایین‌تر از ۲۴۵۰۰
تقاضا ۲ برابر عرضه و تشکیل صف خرید
```

این عبارت‌ها معتبر نیستند، چون معیار عددی یا الگوی مشخص ندارند:

```text
تقاضا خوب باشد
سهم آماده رشد باشد
حجم مناسب باشد
صف فروش سبک باشد
```

در این موارد ابتدا معیار را عددی کنید یا از قاعده‌ساز استفاده کنید.

### معنای قواعد دارای سابقه

- `تثبیت`: تعداد نمونه پیش‌فرض `3` است. فاصله نمونه‌ها همان `intervalMinutes` پایش است.
- `عبور`: حداقل دو Snapshot لازم است. صرفاً بالاتربودن قیمت از سطح به‌معنای عبور نیست.
- `برگشت از محدوده`: ابتدا باید قیمت در بازه ثبت شود و سپس از سقف محدوده خارج شود.
- قواعد صف به داده معتبر ردیف سفارش نیاز دارند. نبود داده، نتیجه `داده ناکافی` می‌دهد؛ نتیجه جعلی ساخته نمی‌شود.
- قدرت خریدار و نسبت تقاضا به عرضه نیز در صورت نبود داده معتبر، `داده ناکافی` می‌دهند.

## مرجع JSON قواعد

JSON ساختاریافته زمانی مناسب است که به عملگرهای کامل، گروه‌های تو‌در‌تو یا تنظیم تعداد نمونه نیاز دارید. هر Expression یکی از دو نوع `group` یا `rule` است.

### گروه شرط‌ها

```json
{
  "type": "group",
  "op": "AND",
  "children": []
}
```

`op` فقط `AND` یا `OR` است. هر گروه باید بین ۱ تا ۳۰ عضو داشته باشد. حداکثر عمق گروه‌ها ۶ است.

### شرط ساده

```json
{
  "type": "rule",
  "field": "lastPrice",
  "operator": "gt",
  "value": 3300
}
```

### فیلدها

| `field` | معنی | واحد متداول |
|---|---|---|
| `lastPrice` | آخرین قیمت | ریال |
| `closePrice` | قیمت پایانی | ریال |
| `dayLow` | کمترین قیمت روز | ریال |
| `dayHigh` | بیشترین قیمت روز | ریال |
| `buyerPower` | قدرت خریدار حقیقی | نسبت |
| `volume` | حجم معاملات | سهم |
| `tradeCount` | تعداد معاملات | عدد |
| `bidAskRatio` | نسبت حجم تقاضا به عرضه | نسبت |
| `sellQueueValue` | ارزش صف فروش | مطابق داده BRSAPI |
| `buyQueueValue` | ارزش صف خرید | مطابق داده BRSAPI |

### عملگرها

| `operator` | پارامتر | فیلدهای مجاز |
|---|---|---|
| `lt`, `lte`, `gt`, `gte` | `value` | `lastPrice`, `closePrice`, `buyerPower`, `volume`, `tradeCount`, `bidAskRatio` |
| `crosses_above`, `crosses_below` | `value` | `lastPrice`, `closePrice` |
| `stabilizes_above`, `stabilizes_below` | `value` و `options` | `lastPrice`, `closePrice` |
| `between` | `min`, `max` | `lastPrice`, `closePrice`, `dayLow`, `dayHigh` |
| `rebounds_from_range` | `min`, `max` و `options` | فقط `lastPrice` |
| `sell_queue_cleared` | ندارد | فقط `sellQueueValue` |
| `buy_queue_formed` | ندارد | فقط `buyQueueValue` |

نمونه تثبیت با پنج Snapshot و تاریخچه ۳۰دقیقه‌ای:

```json
{
  "type": "rule",
  "field": "closePrice",
  "operator": "stabilizes_above",
  "value": 3300,
  "options": {
    "samples": 5,
    "minutes": 30
  }
}
```

نمونه گروه تو‌در‌تو:

```json
{
  "type": "group",
  "op": "AND",
  "children": [
    {
      "type": "rule",
      "field": "lastPrice",
      "operator": "crosses_above",
      "value": 3300
    },
    {
      "type": "group",
      "op": "OR",
      "children": [
        {
          "type": "rule",
          "field": "buyerPower",
          "operator": "gte",
          "value": 1.3
        },
        {
          "type": "rule",
          "field": "bidAskRatio",
          "operator": "gte",
          "value": 2
        }
      ]
    }
  ]
}
```

## پیام تلگرام

پیام فعال‌شدن شرط شامل این موارد است:

- نماد و نوع اقدام
- تعداد سهم
- قیمت پیشنهادی به ریال
- مبلغ تقریبی به تومان
- آخرین قیمت و قیمت پایانی
- قدرت خریدار و نسبت تقاضا به عرضه
- شواهد هر قاعده

## ورود گروهی پایش‌ها

در تب «ورود گروهی»، محتوا را Paste کنید یا فایل UTF-8 با پسوند `.txt` یا `.json` بارگذاری کنید. همیشه ابتدا «پیش‌نمایش» را اجرا کنید. پیش‌نمایش داده‌ای ذخیره نمی‌کند.

### فیلدهای هر پایش

| فیلد متنی | فیلد JSON | الزام | توضیح |
|---|---|---|---|
| `عنوان` | `title` | اختیاری | حداکثر ۱۲۰ نویسه؛ در نبود آن عنوان از نماد و اقدام ساخته می‌شود |
| `نماد` | `symbol` | الزامی | نماد دقیق موجود در فهرست محلی |
| `اقدام` | `actionType` | الزامی | یکی از اقدام‌های جدول بعدی |
| `تعداد` | `quantity` | الزامی | عدد صحیح بزرگ‌تر از صفر |
| `قیمت پیشنهادی` | `proposedPrice` | الزامی | قیمت هر سهم به ریال، بزرگ‌تر از صفر |
| `سقف مبلغ` | `maxAmountToman` | اختیاری | سقف ارزش سفارش به تومان |
| `شروع` | `startAt` | اختیاری | پیش‌فرض `اکنون` |
| `پایان` | `endAt` | اختیاری | پیش‌فرض `یک ساعت دیگر` و الزاماً بعد از شروع |
| `فاصله بررسی` | `intervalMinutes` | اختیاری | دقیقه؛ عدد صحیح حداقل ۱، پیش‌فرض ۱۰ |
| — | `cooldownMinutes` | اختیاری | حداقل فاصله تکرار هشدار؛ کمتر از فاصله بررسی نمی‌شود |
| `شرط` | `sourceText` | برای حالت متنی | عبارت مطابق راهنمای قواعد فارسی |
| — | `expression` | برای حالت ساختاریافته | درخت JSON مطابق مرجع قواعد |

مقدارهای مجاز اقدام:

| فارسی | JSON استاندارد |
|---|---|
| `خرید` | `BUY` |
| `میانگین کم‌کردن` یا `میانگین کم کردن` | `AVERAGE_DOWN` |
| `حد زیان` یا `فروش در حد زیان` | `SELL_STOP_LOSS` |
| `سیو سود` یا `فروش برای سیو سود` | `SELL_TAKE_PROFIT` |

مبلغ محاسبه‌شده برابر `quantity × proposedPrice ÷ 10` تومان است. اگر این مبلغ از `maxAmountToman` بیشتر باشد، پایش رد می‌شود.

### فرمت TXT

هر خط به‌شکل `کلید: مقدار` است. پایش‌ها را با یک خط شامل `---` جدا کنید. خط خالی و خطی که با `#` شروع شود نادیده گرفته می‌شود.

```text
# پایش اول
عنوان: خرید فولاد
نماد: فولاد
اقدام: خرید
تعداد: 10000
قیمت پیشنهادی: 3350
سقف مبلغ: 3500000
شروع: اکنون
پایان: پایان بازار
فاصله بررسی: 10
شرط: قیمت بیشتر از 3300
---
عنوان: حد زیان وبملت
نماد: وبملت
اقدام: حد زیان
تعداد: 5000
قیمت پیشنهادی: 2400
شروع: روز معاملاتی بعد 09:30
پایان: 2026-09-30 12:30
فاصله بررسی: 5
شرط: قیمت کمتر از 2400
```

هر شرط متنی باید در یک خط باشد. برای قواعد چندخطی یا تو‌در‌تو از JSON ساختاریافته استفاده کنید.

### عبارت‌های زمانی

| مقدار | نتیجه |
|---|---|
| `اکنون`، `الان` یا `now` | زمان فعلی ایران |
| `نیم ساعت دیگر` | ۳۰ دقیقه بعد |
| `یک ساعت دیگر` | ۶۰ دقیقه بعد |
| `پایان بازار`، `پایان امروز` | امروز ساعت ۱۲:۳۰ |
| `روز معاملاتی بعد 09:30` | اولین شنبه تا چهارشنبه بعدی، ساعت ۹:۳۰ |
| `فردا 09:30` | مانند روز معاملاتی بعد؛ پنج‌شنبه و جمعه رد می‌شوند |
| `شنبه 09:30` | شنبه بعدی ساعت ۹:۳۰ |
| `شنبه تا آخر وقت` | شنبه بعدی ساعت ۱۲:۳۰ |
| `09:30` | امروز ساعت ۹:۳۰ |
| `2026-09-30 12:30` | تاریخ میلادی محلی ایران |

در TXT می‌توان از ارقام فارسی استفاده کرد. تاریخ صریح فایل فعلاً باید میلادی و به‌شکل `YYYY-MM-DD HH:mm` باشد. همه زمان‌های داخلی به UTC ذخیره و در رابط با `Asia/Tehran` و تقویم شمسی نمایش داده می‌شوند؛ محل سرور روی زمان‌بندی اثر ندارد.

عبارت «روز معاملاتی بعد» فقط پنج‌شنبه و جمعه را رد می‌کند. تعطیلات رسمی موردی هنوز خودکار تشخیص داده نمی‌شوند.

### JSON با شرط ساختاریافته

اگر `expression` وجود داشته باشد یا `inputMode` برابر `builder` باشد، شرط متنی استفاده نمی‌شود. نمونه زیر مستقیماً در تب ورود گروهی قابل Paste یا Upload است:

```json
{
  "monitors": [
    {
      "title": "عبور فولاد با تأیید تقاضا",
      "symbol": "فولاد",
      "actionType": "BUY",
      "quantity": 10000,
      "proposedPrice": 3350,
      "maxAmountToman": 3500000,
      "startAt": "شنبه 09:30",
      "endAt": "شنبه تا آخر وقت",
      "intervalMinutes": 5,
      "cooldownMinutes": 30,
      "inputMode": "builder",
      "expression": {
        "type": "group",
        "op": "AND",
        "children": [
          {
            "type": "rule",
            "field": "lastPrice",
            "operator": "crosses_above",
            "value": 3300
          },
          {
            "type": "group",
            "op": "OR",
            "children": [
              {
                "type": "rule",
                "field": "buyerPower",
                "operator": "gte",
                "value": 1.3
              },
              {
                "type": "rule",
                "field": "bidAskRatio",
                "operator": "gte",
                "value": 2
              }
            ]
          }
        ]
      }
    }
  ]
}
```

JSON باید از قواعد استاندارد JSON پیروی کند: بدون Comment، بدون ویرگول اضافه در انتهای آرایه یا Object، کلیدها داخل کوتیشن دوتایی و اعداد ساختاری با رقم انگلیسی.

پیش‌فرض بازار سهام، شنبه تا چهارشنبه، پیش‌گشایش `08:45`، شروع معاملات `09:00` و پایان بازار عادی `12:30` است. میانبر «روز معاملاتی بعد» پنج‌شنبه و جمعه را رد می‌کند؛ تعطیلات رسمی موردی هنوز باید دستی در بازه پایش لحاظ شوند.

## پشتیبان‌گیری و مهاجرت

تب «پشتیبان و بازیابی» یک فایل `.bmon` می‌سازد. فایل با AES-256-GCM و گذرواژه کاربر رمزگذاری می‌شود و شامل پایش‌ها، رویدادها، نمادها، تنظیمات اتصال، ربات‌ها، کلیدها و رمز مدیر است. برای مهاجرت، نسخه تازه مخزن را روی سرور مقصد نصب کنید و فایل را از همان تب Restore کنید.

گذرواژه Backup داخل فایل یا سرور ذخیره نمی‌شود. بدون آن بازیابی ممکن نیست.

## محدودیت‌های نسخه ۱

- تشخیص صف به وجود داده معتبر ردیف سفارش در پاسخ BRSAPI وابسته است.
- تقویم تعطیلات رسمی هنوز خودکار نیست؛ بازه پایش را کاربر تعیین می‌کند.
- متن فارسی آزاد به همه شکل‌های نگارشی تبدیل نمی‌شود.
- معامله خودکار عمداً وجود ندارد.

پیش از استفاده با پول واقعی، خروجی را در حالت کاغذی بررسی کنید.
